# selecont: сервер закрытого демо

T02, T01, локальная часть T03 и T04–T07 реализованы к 14.09.2026: SQLite-схема v7, FastAPI, отдельные аккаунты, серверные сессии, разные варианты профиля, защищённые аватары, текстовые посты с необязательной одной фотографией и изолированные обсуждения. Страница `/u/grigory` показывает публичное био/фото/посты анониму и соответствующий частный вариант вошедшему другу или члену семьи. Через `/settings/contexts` автор выбирает круг, видит его участников и добавляет людей из алфавитного списка остальных подписчиков; через `/posts/new` явно выбирает Public и/или частные аудитории, а через `/settings/posts` просматривает и удаляет свои посты. На `/p/{post_id}` работают General/For you, вложенные ответы, пометки удалённых комментариев с сохранением ответов и общий лайк. Открытая приватная страница сама закрывается после отзыва или переноса. Для первого знакомства откройте `/demo-guide`.

## Запуск с чистого состояния

### Самый простой способ на Mac

Открой приложение Terminal, вставь эти две команды и нажми Enter после каждой:

```bash
cd selecont
sh apps/api/scripts/start-demo.sh
```

При первом запуске скрипт сам установит зависимости и попросит придумать один пароль. После сообщения `Сервер selecont запущен` открой в браузере [http://127.0.0.1:8000/demo-guide](http://127.0.0.1:8000/demo-guide). Окно Terminal нужно оставить открытым. Остановка — `Ctrl+C`.

Если папка проекта называется иначе, в первой команде укажи путь к ней.

Из корня проекта:

```bash
python3 -m venv apps/api/.venv
apps/api/.venv/bin/python -m pip install -r apps/api/requirements.lock
PYTHONPATH=apps/api apps/api/.venv/bin/python -m selecont.cli --db apps/api/var/selecont.sqlite3 seed-demo
PATH="$PWD/apps/api/.venv/bin:$PATH" \
  SELECONT_DATABASE="$PWD/apps/api/var/selecont.sqlite3" \
  SELECONT_MEDIA_ROOT="$PWD/apps/api/var/media" \
  SELECONT_SECRET_KEY="$(apps/api/.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(48))')" \
  PORT=8000 apps/api/scripts/start-one.sh
```

Seed запросит один пароль не короче 12 символов и создаст `grigory`, `friend`, `family`, `stranger`. Пароль не печатается и не передаётся в аргументах процесса. Сначала открыть `http://127.0.0.1:8000/demo-guide`, затем профиль по ссылке из инструкции. Повторный seed без `--reset-passwords` не заменяет пароль. Отдельный аккаунт создаётся командой `provision HANDLE`; обе команды доступны только локальному оператору, веб-регистрации нет.

Для проверки отзыва в уже открытой сессии:

```bash
PYTHONPATH=apps/api apps/api/.venv/bin/python -m selecont.cli --db apps/api/var/selecont.sqlite3 revoke grigory friend
```

Открытая приватная страница `friend` автоматически очищается и переходит к разрешённой проекции; сам аккаунт остаётся вошедшим и видит Public. Вернуть его в круг можно через авторскую форму `/settings/contexts`.

## Проверки

```bash
apps/api/.venv/bin/python -m unittest discover -s apps/api/tests -v
apps/api/.venv/bin/python -m pip check
```

На 26.09: **95 тестов прошли**. Покрыты независимые сессии, подмена личности, CSRF, истечение/выход, лимит входа, экранирование HTML, миграции v1→v7, файлы и квоты, разные био/аватары, Follow/Unfollow, круги, алфавитное назначение от выбранного круга, скрытые метаданные, read-only предпросмотр, посты с фото и без него, явные аудитории, General/For you, вложенные ответы, лимиты ветки, чужие post/audience/parent/file, два права удаления, пометки с сохранением ответов, общий лайк, авторская разбивка, старый URL/кеш, конкурентный revoke, перенос и повторный запуск.

Пароли хешируются Argon2id. В cookie находится случайный непрозрачный токен; в БД — только SHA-256 токена и срок действия. Личность берётся из сессии. Маршруты не принимают `actor_id`/`viewer_id`. Изменяющие формы проверяют CSRF. Ошибки входа не различают неизвестный username и неверный пароль. Лимит действует по клиенту и аккаунту; это базовая защита закрытого демо, не публичный anti-abuse сервис.

Локально cookie не имеет `Secure`, чтобы работать на `http://127.0.0.1`. Для внешнего HTTPS обязательны `SELECONT_COOKIE_SECURE=1` и постоянный `SELECONT_SECRET_KEY` не короче 32 байт. Ключ не хранить в репозитории.

## Внутренний обработчик фотографий T01

`PhotoStore` принимает байты или бинарный поток. Допустимы статические JPEG, PNG и WebP до 10 МБ и 20 мегапикселей. Реальный формат определяется декодером и должен совпасть с заявленным MIME, если он передан. Изображение ориентируется по EXIF, копируется в новый пиксельный буфер и сохраняется как WebP без EXIF, XMP, ICC и исходных текстовых метаданных.

Файлы находятся в настраиваемом приватном каталоге, например `apps/api/var/media`, с правами `0700`; файлы — `0600`. Клиентское имя не используется в пути. Ключ и имя случайные, запись атомарная. Ограничения: до 10 МБ на результат, 100 МБ на владельца и 512 МБ на один демо-инстанс. Незавершённый asset имеет статус `pending`; `cleanup_pending()` удаляет его после 24 часов вместе со старыми временными и бесхозными файлами.

T03 получает `owner_id` только из сессии. Привязка аватара в одной транзакции проверяет владельца и контекст, связывает ключ с вариантом профиля и переводит asset в `attached`. Составной внешний ключ повторяет проверку владельца на уровне SQLite. Выдача `/media/{opaque-key}` заново проверяет текущее членство при каждом запросе. Путь на диске не является URL; каталог медиа не монтируется как static/public. Ответы имеют `private, no-store`, поэтому условный запрос к старому URL после отзыва тоже сначала проходит проверку и получает 404.

## Один инстанс и подготовленное внешнее размещение

Файл `render.yaml` описывает один Python web service во Frankfurt: Python 3.11.16, один Uvicorn worker, health check `/healthz`, Secure-cookie и один постоянный диск `/var/data`. SQLite находится в `/var/data/selecont.sqlite3`, файлы — в `/var/data/media`, поэтому оба типа данных переживают рестарт одного инстанса. Автоматический деплой выключен.

Это только проверенная конфигурация, а не выполненное внешнее развёртывание. Хост не оплачен и HTTPS-URL продукта не создан. Для завершения внешнего шага нужно связать корневой репозиторий с Render Blueprint, подтвердить платный web service с диском, дождаться health check, затем в Dashboard Shell выполнить интерактивный `seed-demo` с путём `/var/data/selecont.sqlite3` и повторить HTTP-проверки до/после ручного рестарта. Постоянный диск доступен одному сервисному инстансу только во время runtime; поэтому схема специально не запускает SQLite-миграцию в build/pre-deploy.

## T04: профили, круги и подписчики

Follow/Unfollow доступны вошедшему зрителю на странице автора. Подписка оставляет Public до ручного назначения. `/settings/contexts` доступен только текущему автору и показывает только его варианты и его подписчиков. Круги получают независимые био/аватары; новый круг начинает с копии Public. Имена кругов уникальны без учёта регистра, частных кругов не больше 20, био не длиннее 500 символов. Назначение использует текущую серверную сессию и существующую подписку; составной ключ БД сохраняет максимум одно частное членство на пару автор/подписчик.

`/settings/preview/{context_id}` доступен только автору, не изменяет сессию и не содержит форм действий от лица зрителя. Обычная страница зрителя не получает ID, названия и список участников скрытого круга. Пользовательский текст экранируется.

## T05: посты с необязательной фотографией

`/posts/new` требует текст и явный выбор одной или нескольких аудиторий. Можно приложить один настоящий JPEG/PNG/WebP; без файла создаётся текстовый пост. Пустой выбор аудиторий отклоняется и не превращается в отправку «всем». Public — отдельный checkbox; выбор Friends и Family сам по себе не создаёт публичного доступа. Пост, аудитории и необязательная привязка фото записываются одной транзакцией. `post_media` повторяет владельца в составных внешних ключах, поэтому чужой или уже прикреплённый asset отвергается и сервисом, и БД.

`/u/{handle}` выводит доступные текущему зрителю посты без названий/ID других аудиторий; `/p/{post_id}` использует тот же доступ. `/settings/posts` — отдельная авторская проекция с аудиториями и удалением. После отзыва следующий запрос страницы и `/media/{key}` получает 404. Удаление убирает строку поста, аудитории, metadata фото и сам приватный файл. Изменять аудитории после публикации нельзя.

## T06: обсуждения и общий лайк

У поста, опубликованного Public + частному кругу, участник явно выбирает General или For you; первое открытие выбирает For you. У частного поста General отсутствует. Автор видит каждую собственную аудиторию отдельной вкладкой. Зритель никогда не передаёт ID круга: сервер принимает только `public/private` и вычисляет доступный контекст из текущей сессии.

Ответы могут иметь до 12 уровней; одна ветка принимает до 500 комментариев. `parent_id` обязан принадлежать тому же посту и контексту. Комментатор удаляет свой комментарий, автор поста — любой под собственным постом. Удалённая запись превращается в пометку без исходного текста и имени; ответы и соседние ветки остаются. Ответить на пометку нельзя. Любая запись требует сессию и CSRF, а отзыв проверяется заново до записи.

Один пользователь ставит один лайк посту. Все, кому доступен пост, видят общий счётчик; только автор видит username и текущий круг поставившего лайк. Комментарии от этого не объединяются. Схема v6 сворачивает старые реакции одного пользователя из разных веток в одну.

## T07: отзыв открытого экрана

Приватные профили и ветки содержат непрозрачное HMAC-доказательство, связанное с текущими пользователем, ресурсом и точным кругом. Внешний same-origin скрипт перепроверяет его раз в 800 мс без кеша. Отзыв, перенос, истечение сессии или потеря связи сначала удаляют приватный DOM; перенос затем открывает новую разрешённую ветку. ID, название и состав скрытого круга в зрительский HTML не передаются. Полная матрица покрыта автоматическими HTTP-тестами.

## Чего ещё нет

Нет восстановления пароля, регистрации и публичного размещения. Нет альбомов, редактирования текста/аудиторий поста или комментария, progress/preview/crop, уведомлений и блокировки. Переименование/удаление кругов не реализовано. Интерфейс переведён на русский и получил общую навигацию, но это всё ещё простой интерфейс закрытого демо, а не финальный дизайн соцсети. Длинные списки пока не имеют поиска/пагинации, что приемлемо только для нескольких тестовых аккаунтов. Уже переданные байты, screenshot или данные в памяти браузера сервер отозвать не может; polling закрытого демо не заменяет будущий масштабируемый push-канал.

Текущие правила: [PRODUCT-SPEC](../../docs/PRODUCT-SPEC.md). Обзор архитектуры и границ приватности: [ARCHITECTURE](../../docs/ARCHITECTURE.md).

Локальный запуск привязан к `127.0.0.1`; внешний bind нужен только на отдельно настроенном хосте (`SELECONT_BIND_HOST`). При локальном перезапуске со случайным ключом обнови старые открытые формы.
